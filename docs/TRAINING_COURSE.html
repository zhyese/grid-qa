正课内容

1.1 什么是 RAG

RAG = Retrieval-Augmented Generation（检索增强生成）。

传统大模型的问题：

  • 知识截止：不知道企业最新制度。
  • 幻觉：可能编造答案。
  • 不可溯源：无法说明答案来源。

RAG 的解决思路：把企业文档转成向量，检索相关片段后让大模型基于片段回答，并标注来源。

1.2 电网运维场景

电网运维涉及大量规程、案例、设备参数。一线人员遇到问题时，需要快速查资料。RAG 系统可以：

  • 秒级返回答案。
  • 减少翻阅 PDF 的时间。
  • 降低因记忆偏差导致的误操作风险。

1.3 项目功能演示

教师演示：

  1. 打开前端聊天页面。
  2. 输入"主变重瓦斯动作后怎么处理？"
  3. 展示答案、引用角标、来源文档。
  4. 展示检索调试结果。
  5. 展示 Langfuse trace。

案例演示

问题："倒闸操作的安全组织措施有哪些？"

系统返回：

  • 答案正文
  • 引用 [1] [2]
  • 来源文档：某省电力公司《变电运行规程》

动手实验

实验 1-1：访问 http://localhost:5173，用默认账号登录，发送一条问题，截图保存。

常见错误

  • 登录失败：检查 backend 是否 healthy。
  • 页面空白：检查浏览器控制台网络请求。

2.1 六层架构

接入层：Vue3 前端 + nginx
应用层：FastAPI routers + RBAC + 限流
RAG 引擎层：检索 → 增强 → 生成
模型层：LLM + Embedding + Rerank Provider 工厂

基础设施层：Docker Compose + Prometheus + Grafana + Langfuse

2.2 数据流

用户提问 → 前端 → /api/qa/answer/stream → router → qa_service → 缓存/检索/CRAG/图谱/LLM → 流式返回 → 前端渲染。

SQLAlchemy ORM
Milvus 向量数据库
Neo4j 图数据库
Redis 缓存、队列、热配置
MinIO 对象存储

class Base(DeclarativeBase):

    id: Mapped[int] = mapped_column(primary_key=True)
