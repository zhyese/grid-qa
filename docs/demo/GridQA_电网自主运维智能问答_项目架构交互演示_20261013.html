拒答是能力，不是故障

四类 refusedReason（no_recall / rewrite_exhausted / out_of_domain / evidence_contradict）把「答不上来」变成可运营的数据：哪类问题缺知识、缺多少、补完后是否真的变好，全部可度量。

拒答也上监控

CRAG 自纠错

rag/crag.py · crag_v2.py

守门人逻辑：检索质量不达标不硬答——先纠错（改写重检索/邻域扩展），纠不回来就拒答并给出四类归因；拒答不是终点，evidence_gap 闭环让「下次能答」可验证。

CRAG（Corrective RAG）是可信的守门人：检索质量不达标时不硬答——先纠错，纠不回来就拒答并给出理由。V3 开启后从三档离散分级升级为连续置信度五档 + 完整归因。

置信度档位（V3）触发条件（evidence_strength + rerank 分）动作（action×grade 矩阵）
highes ≥ rt_crag_high（默认约 0.75，热调）直接生成，句级引用
medium_high证据较充分生成 + 标注置信度
medium_low证据部分支撑rewrite 改写重检索 / 邻域扩展补证据（opt-in）
lowes ≤ rt_crag_low二次重检索，仍低 → refused
refused纠错穷尽仍无证据拒答 + refusedReason，绝不编造
refusedReason 四类归因含义后续闭环
no_recall知识库无召回进 evidence_gap 自动收集（CRAG_REFUSED_TO_GAP ✓）
rewrite_exhausted改写重检索穷尽rewriteDelta 记录增量，回测评估
out_of_domain域外问题引导到正确知识域
evidence_contradict证据相互矛盾标记知识冲突，进治理队列

改写有评估闭环

QUERY_REWRITE 不是盲改：REWRITE_EVAL_ENABLE ✓ 对每次改写评估增益；REWRITE_ADAPTIVE_ENABLE ✓ 让 classifier 判定正常的 query 直接跳过改写省延迟。

低置信增强

DEBATE_ON_LOW_CONFIDENCE（opt-in）：medium_low/low/refused 触发 debate_agent 三专家裁决共识注入答案并升置信；SUFFICIENCY_GATE（opt-in）：judge.answerability 判证据不足直接降一档。

过自信对齐

CONFIDENCE_OVERCONFIDENT_ENABLE ✓：dislike × 历史 high 置信冲突 → 触发 evidence_gap 复核 + 机器人工对齐，防止"自信地答错"。

rag/raptor.py 对知识库做层次化摘要树，多粒度融合召回——长规程"总-分"结构问答受益。

Agentic 检索 AGENTIC_RETRIEVAL_ENABLE · 默认关

检索从"一次管线"升级为"Agent 多轮工具调用"：模型自主决定查向量、查图谱、查表格、再检索，适合开放域深挖。
